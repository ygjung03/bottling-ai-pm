## 9/6 (토) — M2 타겟 3분할 (시도)

**되면 M2 해결, 밀리면 W4로.**

지금 세 안이 「단품 / 세트 / 미니사이즈」로 나뉘는데 **같은 메뉴의 변형이라 차별성이 약하다.** 타겟을 셋으로 나누고 안을 하나씩 만들면 진짜 다른 안이 나온다.

```
A안  나들이객 20대     한강공원 17-21시, 비상주 86%
B안  퇴근길 30대       뚝섬역 17-21시, 소비 30대 30%
C안  심야 손님         뚝섬역 21-24시, 매출 61%
```

| 단계 | 바뀌는 것 |
|---|---|
| (1) | 타겟 1개 → **3개** 출력 |
| (2) | 각 타겟에 맞는 메뉴 1개씩 |
| (3) | 공통 축이 사라짐. **출력이 세 배** |
| (4) | 순위 기준을 「실행 가능성·매입가·준비 부담」으로. **"어느 손님이 나은가"는 대표님 몫**임을 명시 |

> **밀려도 지장이 없다.** 지금 구조로도 기획안은 나온다. 9/22 마감에 걸리지 않으므로 마지막에 둔다.

> **대시보드가 넘어오면 이것과 바꾼다.** A가 9/5까지 T24b에 착수하지 않으면 9/6에 대시보드를 만들고 M2는 W4로 미룬다.

| 구성 | 데이터 |

**조회 코드는 새로 짤 것이 없다.** `context/builder.py`의 `fetch_market()`과 집계 함수를 그대로 쓴다. Streamlit 차트만 붙이면 되므로 **반나절 규모다.**

```python
from context.builder import fetch_market, _kst, TIMEBANDS, PARK, STATION
```

> **12시간 예측을 여기서 쓴다.** 컨텍스트 빌더에서는 협업 예정일과 무관하다는 이유로 제외했으나, 대시보드는 "지금 상권이 이렇다"를 보이는 화면이라 성격이 다르다.

## T09 — `nearby_stores` 적재 (이월)

호출 규격은 「API검증결과」 V8 참조. 검증이 끝나 있다.

```
GET https://apis.data.go.kr/B553077/api/open/sdsc2/storeListInRadius
    cx=127.0679483 & cy=37.5318919 & radius=1000
    & indsLclsCd=I2 & numOfRows=1000 & pageNo=1 & type=json
```

540건, 페이징 불필요. `distance_m`은 직접 계산.

> **9/21이 마감이다.** 그때까지 없으면 추천 엔진(T15·T16)과 파트너 추천 화면(T24)을 접는다. 접어도 「직접 지정」 경로로 기획안은 나온다.

citydata의 `CULTURALEVENTINFO`로 대체할 수 없음이 확인되었다 (8/29). 두 지점 모두 0건이었고 8/29 광진 뮤직 페스타도 잡히지 않았다.
