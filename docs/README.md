## 어디부터 보면 되나

**처음 보는 경우** — 기획서 1~3장 → 개발명세서 0장(설계 결정)

**개발을 시작하는 경우** — 개발명세서 7장(작업 분해) → 해당 티켓이 참조하는 절

**API를 다루는 경우** — API검증결과에서 해당 V 항목

## 갱신 규칙

- **기획서** — 마일스톤마다 (현장방문 · 중간보고서 · 최종제출)
- **개발명세서** — 설계가 바뀔 때마다 수시
- **API검증결과** — 응답 확인이 끝날 때마다 추가
- **W1_작업계획** — 주 단위로 새로 작성

설계가 바뀌면 **명세서를 먼저 고치고 코드를 고친다.** 반대 순서로 하면 문서가 낡는다.
