# T14 — 고정 테스트셋 채점 기준 (초안)

**작성** B ｜ **검토 요청** A ｜ **2026.8.30 작성 · 9.3 갱신 · 9.19 갱신**

> **9/3 갱신.** 8/31 2차 방문으로 협업 형태가 완제품 매입 하나로 좁혀지고 출력 필드가 바뀌었다. 항목 ①②④를 그에 맞게 고쳤다.
>
> **9/19 갱신.** 컨설턴트가 순위를 매기지 않게 됐다. 세 안이 단품·세트·포장으로 종류가 달라 우열을 가릴 수 없고, 대표가 직접 고른다. 그래서 「채점 대상」이 1위 안에서 각 안으로 바뀌었다. ④에서 맥주 단가 기준을 뺐다 — 고가 맥주가 고마진이 아닐 수 있어 단가로 안을 평가하지 않기로 했다. 테스트셋 8건과 실행 방법은 `tests/test_fixed.py` 에 있다.

## 왜 나누는가

명세서 D5에 적어둔 대로, **자기가 고친 프롬프트를 자기가 채점하면 후해진다.** 그래서 프롬프트 수정은 B가, 채점은 A가 맡는다.

| | 담당 |
|---|---|
| 테스트 케이스 8건 구성 | B |
| **채점 기준 확정** | **A** |
| 프롬프트 수정 (T18) | B |
| **채점 실행 (T18)** | **A** |

이 문서는 B가 만든 초안이다. **그대로 쓰지 마시고 고쳐주시면 좋겠다.** 특히 "이 기준으로 실제로 점수를 매길 수 있는가"를 봐주시면 된다.

---

## 채점 대상

`tests/results_{프롬프트 버전}.json` 에 케이스 8건의 결과가 있다. 케이스마다 안이 세 개(단품·세트·포장. 포장에 맞는 품목이 없으면 둘)이고 순위는 없다.

**케이스마다 안 하나를 골라 채점한다.** 세 안 모두 하면 8 × 3 = 24안이라 부담이 커서다. 어느 안을 고를지는 채점자가 정하되, 같은 프롬프트 버전 안에서는 같은 접근(예: 전부 세트)으로 맞추면 버전 간 비교가 쉽다.

> 8건 × 5항목 = 40회 채점이다. 건당 2분으로 잡으면 약 30분 걸린다.

요약 보기: `python -m tests.test_fixed --report` / 케이스 정의: `tests/fixtures/testset.json`

## 항목별 기준 (초안)

명세서 5-2의 표를 실제 채점이 가능한 수준으로 풀었다. **5·3·1점만 정의하고 4·2점은 그 사이로 둔다.** 5단계를 모두 정의하면 경계가 애매해져 채점이 느려진다.

### ① 실행 가능성

*이 기획안을 대표님이 그대로 실행할 수 있는가*

| 점수 | 기준 |
|---|---|
| **5** | 소요 기간이 3일 이내이고, 협력사가 무엇을 만들어 오는지 명확하다. 바로 전달할 수 있다 |
| **3** | 만들 수는 있으나 준비 기간이 4～6일이거나, 확인해야 할 조건이 한 가지 있다 |
| **1** | 준비 1주 이상이 필요하거나, 납품 조건이 불명확해 그대로는 실행할 수 없다 |

**볼 곳** — `소요_기간` · `협력사_제공` · `보관_조건` · `1회_납품_수량` · `이벤트.기간`

> **완제품 매입이므로 조리 절차는 보지 않는다** (기획서 6-1). 대신 **보관 조건과 납품 수량**이 실행 가능성을 가른다. 당일 소진 품목이면 1회 납품 수량이 곧 판매 가능 수량이다.

### ② 자원 정합성

*있는 것만으로 만들 수 있는가*

| 점수 | 기준 |
|---|---|
| **5** | 협력사가 실제로 만들어 줄 수 있는 것이고, 바틀링은 받아 팔기만 하면 된다 |
| **3** | 대부분 가능하나 협력사에 확인할 것이 한두 가지 있다 |
| **1** | 협력사 보유 자원으로 만들 수 없다. 또는 메뉴명·구성에 없는 재료가 등장한다 |

**볼 곳** — `협력사_제공` · `바틀링_준비` · `메뉴명` · `구성`

> 자동 검증(A4)이 협력사 `blockers` 위반을 이미 잡는다. 루브릭에서는 **자동 검증이 놓친 것**을 본다. 예를 들어 「우유크림 붕어빵」이라 해놓고 재료에 우유크림이 없는 경우는 자동으로 잡히지만, 재료는 맞는데 **그 재료로 그 메뉴를 만들 수 없는 경우**는 사람이 봐야 한다.

### ③ 상권 근거

*왜 이 시간대, 이 손님인지 데이터로 설명하는가*

| 점수 | 기준 |
|---|---|
| **5** | 공략 시간대와 타겟이 실제 관측값에 근거하고, 근거 건수가 함께 적혀 있다 |
| **3** | 근거를 대기는 하나 수치가 아니라 서술이거나, 건수가 빠져 있다 |
| **1** | 근거가 없거나, 입력에 없는 수치를 지어냈다 |

**볼 곳** — `추천_근거.상권_지표` · `선정_사유`

> **지어낸 수치는 자동으로 1점이다.** 입력 컨텍스트와 대조해 없는 값이면 다른 항목이 아무리 좋아도 이 항목은 1점을 준다.

### ④ 페어링 적절성

*맥주와 메뉴가 어울리고, 맥주 매출에 도움이 되는가*

| 점수 | 기준 |
|---|---|
| **5** | 스타일·도수·맛 특성을 근거로 무엇 때문에 어울리는지 적었고, 실제로 그 조합이 말이 된다 |
| **3** | 이유는 적었으나 막연하거나, 근거가 스타일·도수·맛 중 하나뿐이다 |
| **1** | 이유 없이 「잘 어울린다」 수준이거나, 메뉴와 맞지 않는다 |

**볼 곳** — `페어링_맥주.이유` · `메뉴명`(세트는 맥주 종류가 이름에 들어간다)

> 맥주 단가는 보지 않는다(9/19). 고가 맥주가 고마진이 아닐 수 있어 단가로 안을 평가하지 않기로 했다. 페어링은 맛의 적절성만 본다.

### ⑤ 홍보 실효성

*대표님이 그대로 올릴 수 있는가*

| 점수 | 기준 |
|---|---|
| **5** | 홍보 문구를 손대지 않고 그대로 게시할 수 있다. 해시태그도 쓸 만하다 |
| **3** | 뜻은 맞으나 문장을 다듬어야 한다 |
| **1** | 문구가 아니라 문구에 대한 설명이거나, 그대로 쓰면 어색하다 |

**볼 곳** — `홍보_문구` · `해시태그` · `이벤트.명칭`

> 실제로 소리 내어 읽어보시고 어색하면 3점 이하로 본다.

### ⑥ 참신성 — **채점할지 여부부터 검토 필요**

*기존에 안 하던 조합인가*

| 점수 | 기준 |
|---|---|
| **5** | 기존 협업에서 안 해본 조합이고 이야깃거리가 된다 |
| **3** | 익숙한 조합이나 변형이 있다 |
| **1** | 기존 메뉴를 그대로 되풀이한다 |

> **이 항목을 뺄지 여쭙고 싶다.** 이유가 둘이다.
>
> **① 기준이 주관적이다.** 다른 다섯 항목은 문서를 보고 판단할 수 있으나, 참신한지 아닌지는 사람마다 다르다.
>
> **② 판단 근거가 없다.** 기존 협업 3건(제과·디저트 협업·화덕 요리 협업·카페 협업)의 내용을 아직 모른다. 8/31에 여쭙기로 했으나, 못 받으면 "기존에 안 해본 것"인지 판단할 수 없다.
>
> 대안은 **대표님 채점(2층)에만 남기고 T18 튜닝에서는 빼는 것**이다. 튜닝은 「고칠 수 있는 것」을 대상으로 해야 하는데, 참신성은 프롬프트를 고쳐서 올리기 어렵다.

## 여쭙고 싶은 것

### 1. 항목별 가중치를 둘까요

지금은 5개(또는 6개)가 동등하다. 그런데 **실행 가능성이 다른 것보다 중요하지 않은가** 싶다. 실행할 수 없는 기획안은 나머지가 아무리 좋아도 쓸 수 없다.

**제안** — 실행 가능성과 자원 정합성에 가중치 1.5를 주고 나머지는 1.0.

| 항목 | 가중치(안) |
|---|---|
| 실행 가능성 | 1.5 |
| 자원 정합성 | 1.5 |
| 상권 근거 | 1.0 |
| 페어링 적절성 | 1.0 |
| 홍보 실효성 | 1.0 |

**또는 가중치 없이 「실행 가능성이 2점 이하면 다른 항목과 무관하게 불합격」** 같은 규칙을 두는 방법도 있다. 어느 쪽이 채점하기 편하신지 알려주시면 좋겠다.

### 2. 통과 기준을 몇 점으로 볼까요

**이 숫자가 T18 튜닝의 목표가 된다.** 8건의 평균이 이 값을 넘으면 그 프롬프트 버전을 확정한다.

| 안 | 기준 |
|---|---|
| A | 평균 3.5점 이상 |
| B | 평균 4.0점 이상 |
| C | 평균 3.5점 **그리고** 1점을 받은 항목이 없을 것 |

**C를 제안한다.** 평균만 보면 한 항목이 1점이어도 다른 것으로 메워지는데, **실행 가능성이 1점인 기획안은 평균이 4점이어도 쓸 수 없다.**

### 3. 8건을 몇 번 반복할까요

LLM 출력은 매번 다르다. 같은 입력으로 두 번 돌리면 다른 기획안이 나온다.

| 안 | 방식 |
|---|---|
| A | 8건 × 1회 = 8회 채점 |
| B | 8건 × 2회 = 16회 채점 |

**A로 시작하고 결과가 들쭉날쭉하면 B로 늘리는 것**을 제안한다. 채점 부담이 두 배가 되므로 처음부터 B로 가기는 부담스럽다.

### 4. 채점 결과를 어디에 남길까요

**제안** — 구글 스프레드시트에 표를 만들고 A가 직접 입력. B가 그것을 `tests/results_{prompt_version}.json`으로 옮긴다.

| 케이스 | 프롬프트 버전 | 채점한 안 | 실행가능성 | 자원정합성 | 상권근거 | 페어링 | 홍보 | 평균 | 메모 |
|---|---|---|---|---|---|---|---|---|---|
| C1 제과·1차 | 182652b | 세트 | | | | | | | |
| C2 제과·2차 | 182652b | 세트 | | | | | | | |

**메모 칸이 중요하다.** 왜 그 점수를 줬는지 한 줄이라도 있으면 B가 프롬프트를 어떻게 고칠지 알 수 있다. 점수만 있으면 「3점이네」로 끝나고 무엇을 고쳐야 할지 모른다.

> **피자 유형은 `치킨전문점`으로 대응한다** (명세서 3-3). `sales_profile`의 44개 업종에 피자 전용이 없다. 「피자·튀김·그릴」이라는 묶음 이름 자체가 그것을 감안한 것이다.
