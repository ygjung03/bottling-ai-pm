**V9 — 서울시 문화행사 API**

```
GET http://openapi.seoul.go.kr:8088/{KEY}/json/culturalEventInfo/{시작}/{끝}/
```

| 항목 | 내용 |
|---|---|
| 필터 | **파라미터 필터가 동작하지 않는다.** 자치구·날짜를 넣어도 전체 19,503건이 반환된다 |

| 필터 기준 | 자치구(`GUNAME`)가 아니라 **좌표 기준 반경 3km** — 성수동 행사도 포함됨 |
| 기간 | `STRTDATE`～`END_DATE`가 향후 30일과 겹치는 것만 |

**V10 — 광진구청 새소식 게시판** (HTML 파싱)

```
GET https://www.gwangjin.go.kr/portal/bbs/B0000001/list.do
    ?menuNo=200190&pageIndex=1&searchCnd=1&searchWrd=문화행사
```

| 항목 | 내용 |
|---|---|
| robots.txt | **새소식(B0000001)만 허용.** 축제·행사정보 게시판은 금지 |
| 요청 간격 | **`Crawl-delay: 10` — 10초 대기 필수** |
| 검색 결과 | 「문화행사」로 4건. 전체 3,514건을 훑을 필요 없음 |
| 제목 규칙 | `다음주(8/24～8/30) 문화행사 안내` — 정규식으로 기간 추출 |
| 상세 페이지 | **HTML 표.** PDF 아님. `일시`·`장소`만 필수로 뽑고 나머지는 본문으로 |
| 좌표 | **없음.** 장소명에 `뚝섬`·`자양`·`한강공원` 포함 여부로 판단 |

### T11 — 컨텍스트 빌더 (8/25～26) — **A와 공동**

DB 수치를 LLM이 읽을 문장으로 변환한다. **LLM이 아닌 일반 코드다.**

| 역할 | 담당 |
|---|---|
| 집계 로직 (어떤 수치를 어떻게 뽑을지) | **A** |
| 문장 생성 (LLM이 읽을 형태) | **B** |

> DB 경계에 걸쳐 있는 작업이라 명세서상 공동이다. 다만 출력 문장 형식이 곧 (1) 상권분석가 프롬프트의 입력이므로, **B가 원하는 형태를 먼저 정의하고 A에게 필요한 집계를 요청**하는 순서가 효율적이다.

**읽는 것**

| 테이블 | 항목 | 상태 |
|---|---|---|
| `market_context` | 인구·혼잡도·12h예측·음식 결제·날씨 | **이미 쌓이는 중** |
| `sales_profile` | 요일·시간대 매출 | A의 T08 대기 |
| `events` | 인근 행사 | A의 T10 대기 |

> **`market_context`만으로 먼저 만들 수 있다.** 나머지는 A 작업이 끝나면 붙인다.

**출력 원칙** (명세서 6-3)

- 원수치와 해석을 **함께** 표기 — `34% (주중 최고)`
- 데이터 없는 항목은 **"데이터 없음"으로 명시** — 생략하면 LLM이 지어낸다
- 서울시 제공 자연어 문장(`congestion_msg`)은 **참고 인용만**. 비교·순위 해석은 자체 집계로 생성
- **날씨 포함** — 한강 상권에서 강수 여부는 방문객을 좌우한다
- 상권 지표는 **뚝섬역 기준임을 명시** (한강공원은 상권 데이터 없음)
- 생성 문장을 `plans.context_snapshot`에 저장 (재현 + 검증용)

### T14 — 고정 테스트셋 8건 정의 (8/30 일) — **A와 공동**

**프롬프트를 수정하기 전에 반드시 만든다.** 없으면 개선인지 퇴보인지 영원히 판별할 수 없다 (설계 결정 D5).

**왜 필요한가**

프롬프트를 고치고 결과가 나빠졌을 때, 프롬프트 탓인지 입력이 달라진 탓인지 구분할 방법이 없다. 입력 8건을 고정해두고 버전마다 같은 8건을 재생성하면, 통과율·평균점수의 차이가 곧 프롬프트의 차이가 된다.

```
프롬프트 v1 → 8건 생성 → 통과 6/8, 평균 3.2점
프롬프트 v2 → 같은 8건 → 통과 7/8, 평균 3.6점   ← 개선됨
```

**구성**

협력사 유형 4종 × 시점 2종 = 8건

| 축 | 값 |
|---|---|
| 협력사 유형 | 제과·디저트 / 피자·화덕 / 분식 / 카페 |
| 시점 | 성수기 주말 / 비수기 주중 |

- 협력사 자원은 **가상 데이터**로 구성한다 (실제 협력사 입력은 아직 없음)
- 결과는 `tests/results_{prompt_version}.json`에 누적
